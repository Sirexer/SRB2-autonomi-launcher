# Как это устроено

[English](internals.md) | **Русский**

Технические подробности — для тех, кто правит лаунчер или хочет понять, что
он делает. Пользователю это читать не нужно.

## Серверы

### Мастер-серверы

| API | Игры | Запрос |
|---|---|---|
| SRB2 (HTTP) | SRB2 | `<адрес>/servers`; комнаты — `/rooms` |
| Kart (HTTP) | SRB2Kart, Ring Racers, BlanKart | `<адрес>/games/<приложение>/<MODVERSION>/servers?v=2.2` (без `?v=2.2` мастер-сервер Kart Krew не отдаёт список) |
| 2.1 (TCP) | SRB2 Legacy | `хост:порт` (порт 28900): серверы всех комнат и названия комнат |

Последняя версия игры — `<адрес>/games/<приложение>/version` (ответ
`MODVERSION название`). Мастер-сервер Ring Racers не присылает имён серверов —
имя приходит при опросе сервера и запоминается в локальном списке.

### Опрос сервера

Сервер опрашивается по UDP, как это делает игра: пакет с заголовком
`doomdata_t` и контрольной суммой, `PT_ASKINFO` → `PT_SERVERINFO` (название,
карта, режим, игроки, флаги, список аддонов) и `PT_PLAYERINFO`. Если аддонов
слишком много для одного пакета (`SV_LOTSOFADDONS`), остальные запрашиваются
`PT_TELLFILESNEEDED` / `PT_MOREFILESNEEDED`.

Протоколы игр отличаются номерами пакетов, версией пакета и раскладкой
`serverinfo_pak` / `plrinfo` — это таблица `NetProtocol` в
`lib/models/srb2_server.dart` (смещения сверены с `offsetof` по упакованным
структурам из `src/d_clisrv.h` каждой игры):

- **SRB2 2.2** — ответ начинается с `_255` и packetversion, в записи файла
  есть байт «папка», режим — строкой.
- **SRB2 Legacy (2.1)** — без `_255`/packetversion/application, режим — числом.
- **SRB2Kart** — нет refusereason, режим — числом (Race/Battle).
- **Ring Racers** — commit[4] после версии, нет mapname, есть средний уровень
  силы; скин в plrinfo не передаётся (`0xFF`), поэтому персонаж игрока
  ищется по имени.
- **BlanKart** — как Ring Racers, но packetversion 2 и 8-байтовый maphash
  вместо 16-байтового (поля после него на 8 байт раньше); plrinfo — 33 байта,
  скин — UINT16; у файла 64-битный хеш XXH3 и байт compatmode; статус «отдаст
  ли файл» — как в SRB2 (0 — да, 1 — нет, 2 — слишком большой).

Протокол своей игры можно описать в JSON — см.
[custom-games.ru.md](custom-games.ru.md#протокол).

### Аддоны сервера

- Файл на диске ищется по имени (без учёта регистра, на 10 папок вглубь) и
  контрольной сумме: MD5 или, у BlanKart, XXH3-64 всего файла (байты UINT64
  little-endian, как они идут в пакете).
- Источники по порядку: репозитории (по MD5), HTTP-зеркало сервера
  (`<источник>/<имя>?md5=<md5>`, у BlanKart без `?md5=`), сам сервер.
- Скачивание с сервера: `PT_REQUESTFILE` (у Ring Racers, Kart и Legacy — с
  именем файла), затем фрагменты. SRB2 2.2 и Ring Racers подтверждают их
  `PT_FILEACK` / `PT_FILERECEIVED`; SRB2Kart и SRB2 2.1 — старой передачей:
  фрагменты приходят «надёжными» пакетами, лаунчер подтверждает их на уровне
  сети (ackreturn и `PT_NOTHING`), как игра.
- Если в папке загрузок уже лежит другой файл с тем же именем, новый
  кладётся в подпапку `<имя>/<начало суммы>/`; игра находит нужный по сумме.
- Загрузка аддонов до подключения (`-file` в порядке сервера + `+connect`):
  игра требует, чтобы загруженные файлы совпадали со списком сервера. У
  BlanKart отключена: он сверяет и compatmode, а с `-file` игра определяет
  его сама и может не совпасть с сервером.

### Страна сервера

База DB-IP Lite (CC BY 4.0) собирается при сборке в
`assets/geoip/country.bin` (`tools/build_geoip.py`) — диапазоны адресов и
коды стран; поиск — двоичный, адреса никуда не отправляются.

## Палитры

Картинка рисуется последней загруженной `PLAYPAL`; внутри одного файла игра
берёт первую лампу с этим именем (`W_CheckNumForNamePwad`). У BlanKart две
палитры: своя в `main.pk3/Palette/PLAYPAL.pal` и старая палитра SRB2Kart.
Файлы в его режиме совместимости (`d_main`: `srb2.srb`, `gfx.kart`,
`textures.kart`, `chars.kart`, `maps.kart`, `bonuschars.kart`; у аддонов — WAD
`*.kart` или файл с именем на `K`) нарисованы в старой палитре, и их цвета
переводятся таблицей `PALREMAP` (`MakePatch` → `R_DoPaletteRemapPatch`).
`PaletteResolver` (`map_preview.dart`) делает так же, когда в файлах игры есть
`PALREMAP` (он есть только у BlanKart): карты, иконки персонажей и эмблемы
получают палитру своего файла.

## Персонажи

Персонажи ищутся как в игре (`R_AddSkins`): персонаж начинается с lump
`S_SKIN*`, его спрайты идут следом до `S_END`, следующего `S_SKIN` /
`P_SKIN` или `S_START` (в PK3, где у персонажа своя папка, — вся папка).
S_SKIN без `name` тоже считается (иначе сдвинулись бы номера скинов). Сжатые
WAD (`ZWAD`, LZF) читаются.

- **Иконка**: SRB2 — `XTRAC0` (или `XTRAC0C8`, второй кадр общего lump);
  SRB2Kart — lump из `facewant` / `facerank`; Legacy — `face`; Ring Racers —
  `XTRAB0`, затем `XTRAA0`, `XTRAC0`.
- **Портрет**: SRB2 — `XTRAB0`; Legacy — `PicName` из SOC_PLAY, затем
  `charsel` из S_SKIN.
- Нет одной картинки — берётся другая; нет обеих — `STNDA2` / `STNDA2A8`,
  `STNDA8A2` (отражённый), `STNDA0`, `STNDA8` (отражённый), `STNDA1`.
- Иконка перекрашивается: индексы `startcolor`…`startcolor+15` заменяются
  цветом (`prefcolor`, выбранный цвет, цвет команды).
- Соник SRB2 Legacy задан в коде игры — лаунчер добавляет его сам
  (`LIVSONIC` / `CHRSONIC`). Описания Соника, Тейлза и Наклза — из кода игр,
  если аддон не задал своих (`PlayerText` в SOC_PLAY).
- Номер скина игрока на сервере — номер среди персонажей игры и скачанных
  аддонов сервера по порядку; аддоны, которых нет, считаются файлами без
  персонажей (подсказка говорит, что персонаж, вероятно, угадан). Список
  скинов сервера пишется в консоль лаунчера.

## Уровни

- Картинка уровня: `MAPxxP` (SRB2, SRB2Kart), `PICTURE` внутри карты (Ring
  Racers); PNG или Doom-патч с палитрой `PLAYPAL` из аддона или файлов игры.
- Названия — из SOC (`Level 1` / `Level A1` / `Level RR_TEST`,
  `Levelname`, `Act`); номера MAP01–MAPZZ и карты с любыми именами:
  `Maps/<имя>.wad` в PK3 или карта «папкой».
- Режимы карты — по `TypeOfLevel`, как `G_TOLFlag` игр.

## Музыка

- Поиск: lumps `O_<имя>` / `D_<имя>`, в WAD — и между `M_START`/`M_END`, в
  PK3 — `Music/`; названия — `MUSICDEF`. Результат кэшируется по размеру и
  времени файлов (`music/scan_cache.json`).
- Дубликаты — по размеру и CRC-32 содержимого (у PK3 CRC уже есть в архиве).
- MIDI/MUS, модули и музыка приставок сначала отрисовываются в WAV и
  хранятся в `music_render/` (до 1 ГБ, старые удаляются; все — при смене
  `_renderCacheVersion`, её поднимают, когда меняется отрисовка). Свой синтезатор —
  `lib/services/midi_synth.dart`; SoundFont читается с диска частями (только
  сэмплы звучащих нот). Модули — libopenmpt, приставки — libgme, старые OGG —
  libvorbisfile (через FFI).
- **MIDI-устройство**: ноты отправляет отдельный изолят по своему таймеру
  (на Windows — `timeBeginPeriod(1)`); Windows — `winmm` (`midiOutShortMsg`),
  Linux — ALSA sequencer (`snd_seq_event_output_direct`). Перемотка — тишина
  (CC120/123), сброс контроллеров, затем все не-нотные события до нового
  места; громкость — CC7 каналов, умноженные на громкость плеера. Устройством
  владеет один трек за раз; если изолят не ответил, главный поток закрывает
  устройство по его дескриптору.
- Визуализация: спектр FFT движка SoLoud; у MIDI-устройства — уровни
  звучащих нот. Полосы с двумя цветами рисуются одним `drawVertices` с
  цветами вершин: градиентный шейдер на Windows (Impeller через ANGLE) рисуется
  через временную текстуру на каждую полосу и кадр и занимал сотни мегабайт.

## Файлы прогресса

Файлы только читаются, как это делает игра.

- **SRB2 2.2** — `gamedata.dat` (`G_LoadGameData`): время, посещённые и
  пройденные уровни, рекорды, эмблемы, доп. эмблемы, секреты. Уровни, эмблемы
  и секреты — из SOC игры (`srb2.pk3`: SOC_HEAD, SOC_EMBM, SOC_SECR) и аддона.
- **SRB2 Legacy (2.1)** — старый заголовок, 16 доп. эмблем, 32 секрета, без
  лишнего байта у рекорда. 155 эмблем, доп. эмблемы и секреты зашиты в код
  игры (`m_cond.c`) — они в `lib/services/legacy_progress_data.dart`.
- **SRB2Kart** — `kartdata.dat`; медали, доп. эмблемы и секреты зашиты в код
  — в `lib/services/kart_progress_data.dart`.
- **Ring Racers** — `ringdata.dat` и `ringprofiles.prf`: заголовок и UBJSON
  (`g_gamedata.cpp`, `k_profiles.cpp`). Значки — из `gfx.pk3`, перекрашенные
  как в игре (индексы 96–111).
- Данные Legacy и Kart генерирует `tools/gen_progress_defaults.py` из
  исходников игр.
- Хэш имени в файле сверяется с именем, как в игре; чужой файл помечается.
- Свой прогресс у аддона — только при `GameData` в SOC `MainCfg`; эмблемы и
  секреты аддон задаёт только после своего `GameData`.

## Защита сохранений

Файл проверяется так же, как его читает игра (заголовок, длина, разбор до
конца; у слотов — строка `version N` и маркер `0x1d` в конце). Найденный
`GameData` файла кэшируется, пока файл не изменится. Копии — в
`save_backups/<игра>-<код папки>/`, повреждённые — в `save_backups/Damaged`.

## Реплеи

`lib/services/replays.dart`, `lib/ui/replays_tab.dart`. При сканировании у
каждого `.lmp` читаются только первые 16 КиБ и последние 8 КиБ.

- **SRB2 2.2 / SRB2 Legacy 2.1** (`\xf0SRB2Replay\x0f`): `version`/`subversion`,
  `demoVersion`, контрольная сумма MD5 в `0x10..0x1F` (от `0x20..EOF`),
  `PLAY`, `uint16 mapNumber`. При `demoVersion >= 16` в `0x37` хранится
  таблица аддонов (`uint16`, далее `cstr name` + 16-байтный MD5), затем время,
  счёт, кольца, имя игрока, скин и цвет. Для `demoVersion < 16` (2.1 и ранние
  2.2) аддоны подбираются по имени подпапки через `MainCfg → GameData` в SOC
  или по имени архива (`resolveAddonsByFolder`).
- **SRB2Kart** (`\xf0KartReplay\x0f`, `version < 2`): `title[64]`, MD5 в
  `0x50..0x5F` (по `0x60..checksumEnd`, где `checksumEnd` — сразу после
  последнего `\xff\x80` или `length - 1`), `PLAY`, `uint16 mapNumber`,
  `mapmd5[16]`, `demoflags`, `gametype` (0 Race, 1 Battle), `uint8 numAddons` в
  `0x78` (`cstr name` + 16-байтный MD5). В Time Attack время, netvars и игрок
  читаются из заголовка; в завершённых сетевых заездах итоги победителя
  (16-байтные имя, скин, цвет и `uint32` время/счёт) идут после `\xff\x80`.
- **Ring Racers** (`\xf0KartReplay\x0f`, `version >= 2`): `title[64]`, MD5 в
  `0x50..0x5F`, `PLAY`, `cstr mapName`, `mapmd5[16]`, `demoflags[2]`,
  `cstr gametype`, байт флагов, `uint8 numAddons`, `uint8 nSkins` (`16 + 6`
  байт на скин) и блок UBJSON `standings` в конце файла.
- **BlanKart** (`\xf0BlanReplay\x0f`, `version 2`): `title[64]`, 64-битный
  чексум XXH3-64 LE в `0x50..0x57` (по `0x60..pos(\xff\x80)+2`), `PLAY`,
  `cstr mapName`, `maphash[8]`, `demoflags`, `cstr gametype` (и строки
  сервера/MOTD при `demoVersion >= 11`), `uint8 numAddons` (в записи:
  `cstr name`, 8-байтный XXH3-64 и байт `compatMode`) и итоги после `\xff\x80`
  (`cstr` при `demoVersion > 12`).
- **Патчинг заголовка (`SRB2AL-Replays/temp/replay.lmp`)**: вместо `-force`
  при изменении набора аддонов, подключении доп. аддонов или использовании
  файла с диска с отличающейся суммой (`exact == false` через
  `LocalFileIndex.firstByName`) `ReplayScanner.prepareTempReplay` перезаписывает
  таблицу аддонов и пересчитывает контрольную сумму заголовка. Папка `temp/`
  игнорируется сканером.

## 3D-модели

`lib/services/model_packs.dart`, `model_mesh.dart`; Настройки → Модели
(`lib/ui/models_settings.dart`, просмотр — `model_preview_dialog.dart`,
`model_viewer.dart`).

- **Форматы** (`ModelFormat`, по `hw_md2.c` каждой игры): SRB2 Legacy
  (2.1) — `md2.dat`/`md2/`, `%19s`, без `PLAYER`, только MD2 и только в
  домашней папке; SRB2 —
  `models.dat`/`models/`, имя `%25s`; SRB2Kart — `mdls.dat`/`mdls/`, `%19s`,
  без префикса `PLAYER`; Ring Racers — `%23s`; BlanKart читает `models.dat`,
  затем `blanmodels.dat`. Путь везде `%31s`. Список читается через
  `fscanf("%Ns %31s %f %f") == 4` — первая неправильная строка обрывает
  чтение (`ModelDat.parse` делает так же и сообщает, где). Игра ищет сначала
  в своей домашней папке, потом рядом с exe: папка игры лаунчера — это
  домашняя (рабочая) папка.
- **Текстуры**: `<путь модели без расширения>.png` (или `.pcx`); для цвета
  игрока — `_blend.png`. Без PNG игра натягивает на модель спрайт объекта
  (`adjustTextureCoords`).
- **Библиотека**: `model_packs/<игра>/<набор>/pack.json` + `files/` (только
  файлы из списка, в написании из списка); `setup.json` — порядок,
  выключенные наборы, ручной выбор. Архивы моделей из репозиториев скачиваются
  в `models/<игра>/<набор>/<версия>/` в папке данных лаунчера (а не в
  `DOWNLOAD` игры). Поддерживаются вложенные папки, пути с `\` в `.zip`,
  несколько версий в одном архиве и разбор `README` / `Read Please!.txt` через
  `ModelDat.extractFromReadme`, если `.dat` не найден. Внутри набора действует
  последняя строка с именем (как в игре).
- **Сборка**: выбранная версия каждого имени; путь сохраняется, совпадение с
  файлом другого набора — в `P<n>/…`, слишком длинный — `P<n>/<файл>` или
  `P<n>/M<k>.md3`. Установка: файлы копируются в `<папка>.srb2al-new`, старые
  папка и список переименовываются в `<папка>.srb2al-backups/<дата>/`, затем
  новые — на место (хранятся пять копий); метка `.srb2al-models.json` в
  папке — «поставил лаунчер».
- **Отражение**: игра переводит вершины модели в GL как (x, z, −y), а мир — как
  (x, z, y) (`DrawModelEx`; 2.1 так же переводит MD2 в `md2_readModel`),
  поэтому в игре модель отражена относительно файла; просмотр тоже
  переворачивает Y.
- **Просмотр**: MD3 (вершины ×1/64, кадры по именам: `SPR2_STND+i00` → STND,
  `SUPER…`) и MD2 (каждый угол треугольника — своя вершина); рисует
  `rasterizeModel` (`model_raster.dart`) с проверкой глубины по пикселям, как
  OpenGL в игре — сортировка целых треугольников прятала мелкие детали вроде
  зрачков; пиксели текстуры прозрачнее половины пропускаются; модель с
  текстурой не затеняется (цвета как в файле), без текстуры — свет по граням. Цвет игрока —
  `blendSkinColor`, перенос `HWR_CreateBlendedTexture` (обычные цвета).

## Обновление лаунчера

- Список релизов — API GitHub (`/repos/…/releases`); если тот отказывает
  (без входа — 60 запросов в час с адреса, ответ 403), — лента
  `releases.atom` (файлы тогда ищутся по именам из CI, без SHA-256).
- Новее — релиз, опубликованный позже релиза этой версии (`BUILD_VERSION`);
  у сборки без версии — опубликованный позже времени сборки; локальная
  сборка без даты при запуске не проверяет.
- Файл сверяется по размеру и SHA-256 (поле `digest` в API).
- **Windows**: zip распаковывается в `.update` рядом с лаунчером; заменяемые
  файлы переименовываются в `*.old` (работающий exe и его dll так можно),
  новые встают на их место; при ошибке всё возвращается. Список `*.old` —
  в `.update_old.txt`, они удаляются при следующем запуске. `pointer.txt`, если
  он уже есть, остаётся.
- **Linux**: новый AppImage качается рядом (`$APPIMAGE.new`) и
  переименовывается поверх старого.
- Затем `antd` останавливается, лаунчер запускается с `--new-instance` и
  закрывается.

## Один лаунчер за раз

Windows — именованный mutex в `windows/runner/main.cpp`; Linux —
единственность GtkApplication через D-Bus (`linux/runner/my_application.cc`;
без сессионной шины проверки нет). `--new-instance` её пропускает.

## Autonomi (antd)

- `antd` лежит в сборке (папка `antd` рядом с программой) вместе с
  лицензиями; при первом запуске копируется в папку данных
  (`antd/<версия>/`) и запускается оттуда. Если его нет (запуск из
  исходников) или версия не та, лаунчер качает его с GitHub, а если не вышло,
  — с зеркала на GitLab, и сверяет с SHA256SUMS того же релиза.
- Порт — `127.0.0.1:8082`. Чужой отвечающий демон используется; зависший
  свой (из папки данных) закрывается и запускается заново. После нескольких
  тайм-аутов подряд демон перезапускается сам (не чаще раза в минуту).

## Отрисовка

- Рисует Impeller (по умолчанию во Flutter); ключ `--skia` включает Skia.
  Какой — в журнале (`renderer: ...`).
- Картинка фона темы декодируется один раз, сразу уменьшенной (до размера
  экрана или 2048 px), и размывается один раз — а не слоем размером с окно на
  каждом кадре.
- Прозрачность окна: Linux — `gtk_widget_set_opacity` через канал
  `srb2al/window` в раннере; Windows — слоистое окно (`WS_EX_LAYERED`).
  Подложка Windows 11 — `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` и
  рамка, растянутая на всё окно.

## Данные и кэши

| Файл | Что |
|---|---|
| `shared_preferences.json` | Настройки |
| `addon_contents_cache.json` | Что внутри аддонов |
| `music/scan_cache.json` | Музыка в файлах |
| `music_render/` | Отрисованные MIDI и модули |
| `cache/images/` | Обложки аддонов |
| `themes/` | Свои темы |
| `games/` | Иконки своих игр |
| `save_backups/` | Копии сохранений |
| `model_packs/` | Наборы моделей (Настройки → Модели) |
| `models/` | Архивы моделей из репозиториев |
| `logs/launcher.log` | Журнал |
| `antd/` | Демон Autonomi |
