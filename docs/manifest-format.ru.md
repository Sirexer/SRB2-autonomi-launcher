# Формат репозитория аддонов (index_version 2)

[English](manifest-format.md) | **Русский**

Репозиторий — один JSON-файл. Его добавляют в лаунчер по адресу Autonomi,
текстом или файлом (кнопка «Add Repository»).

## Пример

```json
{
  "index_version": 2,
  "repository_name": "SRB2 Hub",
  "mods": [
    {
      "id": "knockout",
      "name": "KNOCKOUT",
      "category": "Characters",
      "uploader": "Scarf The Wolf",
      "description": "HEY IT'S ME!! IT'S VERITY!!!",
      "tags": ["character", "demo"],
      "image_hash": "<адрес картинки в Autonomi>",
      "files": [
        {
          "name": "CL_Knockout-V1.4a(Demo).pk3",
          "version": "V1.4a(Demo)",
          "hash": "<адрес файла в Autonomi>",
          "md5": "<md5 файла>",
          "size": 170309009,
          "changelog": "First demo"
        },
        {
          "name": "CL_Knockout-V1.4b(Demo).pk3",
          "version": "V1.4b(Demo)",
          "hash": "<адрес файла в Autonomi>",
          "md5": "<md5 файла>",
          "size": 170400000,
          "changelog": "Bug fixes"
        }
      ]
    }
  ]
}
```

## Поля аддона

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Уникальный идентификатор внутри репозитория. |
| `name` | да | Название. По нему же называется папка `DOWNLOAD/<name>/`. |
| `category` | нет | Категория в списке; без неё — «Other» (в конце списка). |
| `uploader` | нет | Кто загрузил аддон в репозиторий (строка или список). Старое поле `authors` тоже читается. Может быть своим у версий (ниже). |
| `description` | нет | Описание. Может быть своим у версий. |
| `tags` | нет | Теги (для поиска и скрытия). Может быть своим у версий. |
| `games` | нет | Для каких игр аддон (см. «Игры»). По умолчанию `["srb2"]`. Может быть своим у версий (ниже). |
| `image_hash` | нет | Адрес картинки в Autonomi. |
| `files` | да | Файлы всех версий (см. ниже). |

### Поля по версиям

`tags`, `uploader`, `description` и `games` пишутся либо как раньше — одно
значение на все версии, либо словарём «версия → значение» (ключ — `version`
файлов):

```json
"tags": {
  "2.0.2": ["workshop", "blue_sphere", "maps"],
  "2.0.3": ["workshop", "blue_sphere", "maps", "lol"]
},
"uploader": {"1.0": "Old Person", "2.0": ["A", "B"]},
"games": {"2.0.2": ["srb2"], "2.0.3": ["srb2", "drrr"]},
"description": "Одно описание на все версии"
```

У версии без своей записи значение берётся от ближайшей более старой
версии из словаря (а если старее нет — от ближайшей более новой), так что
писать каждую версию не нужно — только те, где что-то поменялось. Карточка
аддона показывает значения выбранной версии; список, поиск и панель тегов —
значения последней версии. `games` у самого файла важнее `games` аддона: в
примере выше версии 2.0.3 и новее есть и в Ring Racers, а 2.0.2 — только в
SRB2.

## Поля файла

| Поле | Обязательно | Описание |
|---|---|---|
| `name` | да | Имя файла (`.pk3`, `.wad`, `.lua`, `.soc`). Только имя, без папок. |
| `version` | да | Версия, к которой относится файл. |
| `hash` | да | Адрес файла в Autonomi. |
| `md5` | да | MD5 файла — по нему лаунчер проверяет скачанное, а SRB2 находит файл на серверах. |
| `size` | нет | Размер в байтах (для процентов загрузки). |
| `changelog` | нет | Что изменилось в этой версии. |
| `games` | нет | Для каких игр этот файл; если не указано — как у аддона. |
| `type` | нет | Тип файла: `"addon"` (по умолчанию), `"models"`, `"app_windows"`, `"app_linux"`. `"models"` — набор 3D-моделей (импортируется в библиотеку моделей). `"app_windows"` и `"app_linux"` — кастомные сборки игры; отображаются только на соответствующей ОС и запрашивают папку для установки. |

## Теги

Теги — свободные строки; лаунчер приводит их к нижнему регистру. По тегам
ищут и скрывают аддоны (кнопки ＋/－ у тега, скрытые теги в Настройки → Аддоны),
поэтому лучше одно слово без пробелов и не начинающееся с `-` (`-тег` в
поиске — исключение). Тег ищется по точному совпадению: `oldschool` и
`oldshcool` — разные теги, поэтому пишите их так, как в списке ниже.

Рекомендуемые теги — чтобы в разных репозиториях они совпадали.

### Отметки

| Тег | Значение |
|---|---|
| `featured` | Выбор кураторов репозитория. |
| `open_assets` | Ресурсы аддона разрешено использовать в своих аддонах. |
| `mixels` | Разное разрешение графики: спрайты, объекты или текстуры в другом разрешении рядом с обычными. |
| `w.i.p.` | В разработке (work in progress). |
| `demo` | Демоверсия. |

### Назначение

| Тег | Значение |
|---|---|
| `mod_dev` | Для создателей карт и модов: ресурсы (текстуры, объекты, звуки), инструменты для тестирования и отладки. Игрокам не нужен. |
| `serv_management` | Для тех, кто держит сервер: администрирование, модерация, служебные команды (например, LithiumCore). Для одиночной игры не нужен. |

### Источник — `source:`

| Тег | Откуда аддон |
|---|---|
| `source:ws` | SRB2 Workshop. |
| `source:mb` | SRB2 Message Board. |
| `source:gb` | GameBanana. |
| `source:sb` | SKYBASE. |
| `source:game_server` | Скачан с игрового сервера. |
| `source:unknown` | Источник неизвестен. |

### Правила Message Board — `section:`

| Тег | Значение |
|---|---|
| `section:blue_sphere` | Аддон соблюдает правила Message Board. |
| `section:red_sphere` | Аддон нарушает правила Message Board: за сервер с ним можно получить бан на мастер-сервере. |

### Содержимое

| Тег | Что есть в аддоне |
|---|---|
| `maps` | Уровни. |
| `characters` | Персонажи. |
| `assets` | Ресурсы: графика, звуки, объекты. |
| `lua` | Lua-скрипты. |
| `sprites` | Спрайты. |
| `textures` | Текстуры. |
| `music` | Музыка. |
| `badniks` | Враги (бадники). |
| `bosses` | Боссы. |
| `gimmicks` | Механики уровней (новые объекты и устройства на картах). |

### Карты

| Тег | Значение |
|---|---|
| `single_map` | Одна карта. |
| `map_pack` | Набор карт — вместе с одним из размеров ниже, чтобы ＋`map_pack` находил все наборы. |
| `small_map_pack` | Небольшой набор: 2–5 карт. |
| `medium_map_pack` | Средний набор: 6–15 карт. |
| `large_map_pack` | Большой набор: 16 карт и больше. |
| `linear_maps` | Линейные карты: один основной путь. |
| `nonlinear_maps` | Нелинейные карты: несколько путей, исследование. |
| `slope_abuse` | Очень много склонов, в том числе без пользы для игры. |
| `minimum_slopes` | Склонов немного. |
| `no_slopes` | Без склонов. |

### Стиль карт — `mapstyle:`

| Тег | Стиль |
|---|---|
| `mapstyle:oldschool` | Классический «ванильный» стиль времён Final Demo, 2.0 и ранней 2.1 (Mystic Realm, Tortured Planet, Acid Missile, Chaos Domain…). |
| `mapstyle:vanilla` | Стиль ванильных карт 2.1/2.2 (Furen, Blast Mania, Equinox, часть карт OLDC/ULDC и SUGOI). |
| `mapstyle:pancake` | Мало вертикальности, широкие раскинутые карты (карты Zaxel, Sonic1983, Sol Sestancia). |
| `mapstyle:newschool` | Современная школа: очень широкие коридоры, много склонов без игровой пользы, увеличенные текстуры и объекты (большинство карт Othius, MRCE, многие карты OLDC/ULDC). |
| `mapstyle:mixed` | Карты, которые сами смешивают стили или не подходят ни под один из стилей выше (часть карт SUGOI, большинство карт Cyberdime и Dimension Glaber). |

Стиль ставится по наличию, а не только преобладающий: у набора карт —
каждый стиль, которого в нём заметная доля (хотя бы 2 карты или около
четверти набора), а не из-за одной карты. Иначе у больших наборов окажутся
все стили, и фильтр потеряет смысл. Набор из разных стилей видно по
нескольким тегам `mapstyle:`, поэтому `mapstyle:mixed` — для самих карт со
смешанным стилем.

### Режимы — `gametype:`

`gametype:<режим>` — аддон (карты, механика) для этого режима игры. Имя
режима — как в игре, строчными буквами, пробелы заменяются на `_`:
`gametype:co-op`, `gametype:competition`, `gametype:race`, `gametype:ctf`,
`gametype:ringslinger`; режимы из аддонов — так же (`gametype:rk` — Rollout
Knockout). Отдельно, без приставки: `hangout` — карты и аддоны для общения
на сервере, `emerald_hunt` — поиск изумрудов.

### Порты — `port`

| Тег | Значение |
|---|---|
| `port` | Порт из другой игры — вместе с одним из уточнений ниже. |
| `clear_port` | Перенесено как есть, без изменений. |
| `almost_clear_port` | Почти без изменений. |
| `edited_port` | Заметно изменено. |
| `extended_port` | Дополнено новым содержимым. |

### Рекомендуемые к сокрытию теги — `hide_tags`

```json
"hide_tags": ["hidden"]
```

Теги, аддоны с которыми репозиторий советует скрывать. Когда репозиторий
подключают или он обновляется, лаунчер добавляет новые из них в скрытые теги
(Настройки → Аддоны), если включено «Автоматически добавлять рекомендуемые к
сокрытию теги в список скрытых тегов» (по умолчанию включено; та же галочка
есть в окне «Подключить репозиторий»). Без вопросов; при включении настройки
добавляются теги всех подключённых репозиториев. Убранный из скрытых тег
вернётся при следующем обновлении репозитория — чтобы этого не было,
выключите настройку.

### Группы тегов — `tag_groups`

Панель тегов в лаунчере раскладывает теги по группам — их задаёт
репозиторий полем `tag_groups` (рядом с `mods`):

```json
"tag_groups": [
  {
    "id": "source",
    "color": "#4FC3F7",
    "tags": ["source:ws", "source:mb", "source:gb", "source:sb", "source:game_server", "source:unknown"]
  },
  {
    "id": "content",
    "color": "#81C784",
    "tags": ["maps", "characters", "lua", "sprites", "textures", "music", "original music", "badniks", "bosses"]
  }
]
```

- `id` — имя группы.
- `name` — название группы в панели (не обязательно). Лаунчер своих названий
  групп не задаёт: без `name` показывается `id`.
- `color` — цвет группы, `#RRGGBB` (или `#AARRGGBB`).
- `tags` — теги группы. Тег попадает в первую группу, где он перечислен;
  неперечисленные — в «Другие». Тег с приставкой своей группы (`source:ws`
  в группе `source`) показывается без неё. В поиске и у аддона тег пишется
  с группой: `source:workshop` (тег `workshop` из группы `source`); тег без
  группы — `other:тег`.
- Порядок групп — как в списке; теги внутри группы — по числу аддонов.
- Если подключено несколько репозиториев, группы с одним `id` объединяются:
  теги складываются, цвет — из первого репозитория.
- Если ни один репозиторий не задаёт `tag_groups`, лаунчер раскладывает
  теги сам: `группа:имя` — по приставке, теги без приставки — по встроенному
  списку (`lib/services/tag_groups.dart`).

## Версии

- Файлы с одинаковым `version` — это **одна версия**. Если версия состоит из
  нескольких файлов (например, pk3 и тестовая карта), у них одинаковый `version`.
  Changelog версии — первый непустой `changelog` среди её файлов.
- Версии сортируются от новой к старой «как числа»: `2.10` новее `2.9`,
  `V1.4b` новее `V1.4a`. Самая новая помечается как latest. Порядок файлов в
  манифесте значения не имеет.
- У каждой версии своя папка: `DOWNLOAD/<name>/<version>/<файл>`. Версии лежат
  рядом и не мешают друг другу: SRB2 ищет аддоны по имени и MD5 во вложенных
  папках, поэтому на сервере найдётся нужная.
- В лаунчере версия выбирается в карточке аддона. Если файлы аддона стоят в
  очереди запуска, очередь переключается на выбранную версию (когда она скачана).

## Игры

Лаунчер работает с несколькими играми; текущая выбирается в заголовке окна, и в
списке видны только аддоны (и файлы) для неё.

| Код | Игра |
|---|---|
| `srb2` | Sonic Robo Blast 2 (2.2) |
| `srb2legacy` | SRB2 Legacy (2.1) |
| `srb2kart` | SRB2Kart (1.6) |
| `drrr` | Dr. Robotnik's Ring Racers (2.4) |
| `id` своей игры | Своя игра (форк), например `srb2blankart` — BlanKart; см. [custom-games.ru.md](custom-games.ru.md) |

Поле `games` — список кодов (регистр не важен; `"RingRacers"` тоже понимается
как `drrr`, `"kart"` — как `srb2kart`). Своя игра с `base_addons` показывает и
аддоны своей основы: BlanKart — аддоны SRB2Kart. Его можно указать у аддона — это значение по умолчанию для всех
его файлов (или по версиям, см. «Поля по версиям») — и переопределить у
отдельного файла:

```json
{
  "id": "sonic-pack",
  "name": "Sonic Pack",
  "games": ["srb2", "drrr"],
  "files": [
    { "name": "CL_Sonic.pk3", "version": "1.0", "hash": "...", "md5": "..." },
    { "name": "KC_Sonic.pk3", "version": "1.0", "hash": "...", "md5": "...", "games": ["drrr"] }
  ]
}
```

Здесь в SRB2 видна версия 1.0 с одним файлом `CL_Sonic.pk3`, а в Ring Racers — оба
файла. Аддоны без `games` считаются аддонами для SRB2.

Файлы скачиваются в папку загрузок игры: у SRB2, SRB2 Legacy и SRB2Kart —
`DOWNLOAD/<name>/<version>/`, у Ring Racers и BlanKart —
`addons/DOWNLOAD/<name>/<version>/`.

## Совместимость со старым форматом (index_version 1)

Старые манифесты, где `version` и `changelog` указаны у аддона, а не у файлов,
по-прежнему читаются: эти значения применяются ко всем файлам аддона (одна версия).
Если в файле указан свой `version`, он важнее версии аддона.

## Частые ошибки

- JSON не допускает запятую после последнего элемента (`"size": 1,}`) и требует
  запятые между полями.
- У каждого файла свои `hash` и `md5`. Одинаковые `md5` у разных файлов — почти
  всегда ошибка копирования: такой файл не пройдёт проверку после скачивания.
